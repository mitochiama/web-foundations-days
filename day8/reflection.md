# Day 8 Reflection

The most difficult part of the course for me was understanding APIs and how
servers communicate with browser applications. I needed to connect the code
in the browser with the requests sent to a server and the responses returned.
Exploring freeCodeCamp resources and other tutorials helped me break these
ideas into smaller steps. Their explanations and examples helped me understand
HTTP methods, response status codes, and error handling. Working through
QuickNotes also made these concepts more concrete because I could see how
loading, creating, and deleting notes depended on API requests.

I have not yet received feedback on my QuickNotes capstone, so I cannot name
an improvement based on reviewer comments. From my own assessment, I would
strengthen the way I test the API client. I would check failed requests,
overlapping actions, and repeated IDs systematically to confirm that the
interface stays consistent and preserves the user's work. Once feedback is
available, I will use it to decide which improvements deserve priority.

Next, I want to learn how to create more robust system designs. I want to
become better at estimating traffic, choosing suitable database structures,
and explaining architectural trade-offs. TicketHub has shown me why a design
must consider simultaneous requests, temporary holds, payment failures, and
recovery. My next goal is to build small backend services and practise testing
these situations, so I can connect design decisions with actual system behaviour.
